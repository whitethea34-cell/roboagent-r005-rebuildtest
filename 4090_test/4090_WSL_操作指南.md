## 1. 进入 WSL 子系统

```bash
wsl ~
```

- **作用**: 从 Windows 进入 WSL2 Linux 子系统（`~` 表示直接进到 WSL 的家目录，避免留在 Windows 路径）
- **预期输出**: 提示符变成类似 `user@hostname:~$` 的 Linux 格式
- **风险**: 无

```bash
# 验证已进入 WSL（内核信息会显示 Linux 而非 Windows）
uname -a
```

- **预期输出**: 包含 `Linux` 和 `WSL2` 字样

## 2. 切换工作目录

```bash
cd /mnt/e/Claude_roboagent/r005_rebuildtest
```

- **作用**: 切换到项目目录（注意 Windows 的 `E:\` 在 WSL 中变成 `/mnt/e/`）
- **参数说明**:
  - `/mnt/e/` — WSL 把 Windows 的 E: 盘挂载在这里
  - 后面路径和 Windows 一致，但斜杠方向从 `\` 改为 `/`
- **预期输出**: 无输出（切换成功）
- **验证**:

```bash
pwd
# 应显示: /mnt/e/Claude_roboagent/r005_rebuildtest

ls -F
# 应看到: 4090_test/  docker-compose.r005.yml  test_interactive.py  ...
```

- **注意**: WSL 的文件系统和 Windows 文件系统有编码差异。中文字符在 `/mnt/e/` 路径下可能出现损坏。遇到 Unicode 错误时，把脚本复制到 WSL 内部路径（如 `~/`）执行。

### [备选] 复制到 WSL 内部运行（遇到编码问题时使用）

```bash
# 把整个测试目录复制到 WSL 家目录
cp -r /mnt/e/Claude_roboagent/r005_rebuildtest ~/r005_rebuildtest
cd ~/r005_rebuildtest
```

- **作用**: 复制项目到 WSL 内部文件系统，避免 Windows NTFS → WSL 的编码转换问题
- **风险**: 复制后的文件和原始文件是两份，修改不同步。用完记得删

## 3. 检查环境

### 3.1 检查 GPU 可用性

```bash
nvidia-smi
```

- **作用**: 显示 NVIDIA GPU 状态（驱动版本、CUDA 版本、显存占用、正在运行的进程）
- **预期输出**: 表格显示 RTX 4090，`CUDA Version: 12.4`
- **排查**:
  - `command not found` → 未安装 NVIDIA 驱动或 CUDA。检查 Windows 是否装了 NVIDIA 驱动
  - `No devices were found` → WSL 未识别 GPU。检查 Windows 的 `nvidia-smi` 是否正常
- **风险**: 无

### 3.2 检查 Docker 可用性

```bash
docker info
```

- **作用**: 显示 Docker 系统信息
- **预期输出**: 大量 JSON 格式信息，结尾无报错
- **排查**:
  - `command not found` → 未安装 Docker。需 `sudo apt install docker.io`
  - `Cannot connect to the Docker daemon` → Docker 服务未启动。执行 `sudo service docker start`
  - WSL 需要 Docker Desktop for Windows 支持 GPU 转发

```bash
# 检查 Docker Compose 是否可用（新版 Docker 用 "docker compose"，无横杠）
docker compose version
```

- **预期输出**: `Docker Compose version v2.x.x`
- **注意**: 新版 Docker 用 `docker compose`（中间有空格），旧版用 `docker-compose`。本项目使用新语法。

## 5. 停止并清理旧容器

### 5.1 逐个停止（安全方式）

```bash
# 停止容器（允许优雅退出，等待进程保存状态）
docker stop qwen35-4090 robobrain-4090 qwen35-08b-4090

# 如果有更旧版本的容器
docker stop qwen35-4090-server robobrain-4090-server
```

- **参数说明**:
  - `stop` — 发送 SIGTERM 信号，给进程 10 秒保存时间后 SIGKILL
  - 可以同时接多个容器名，空格分隔
- **风险**: 停止容器会中断正在进行的推理任务。确认无人使用后再停。

```bash
# 删除已停止的容器（释放容器名和磁盘）
docker rm qwen35-4090 robobrain-4090 qwen35-08b-4090
```

- **参数说明**:
  - `rm` — remove，删除容器（已停止的才能删）
- **风险**: 删除后容器的日志（`docker logs`）也会丢失。如需保留日志，先导出：

```bash
docker logs qwen35-4090 > ~/qwen35-backup.log 2>&1
```

### 5.2 一键清理（快捷方式）

```bash
# 停止并删除所有含 4090 的容器（⚠ 注意：会误删其他含 4090 字样的容器）
docker ps -a | grep "4090" | awk '{print $1}' | xargs docker stop | xargs docker rm
```

- **风险**: ⚠️ 高危操作。确认没有其他重要容器后再执行。不熟悉时不推荐使用。

### 5.3 验证清理结果

```bash
docker ps -a
```

- **确认**: 上述容器的 Status 列显示 `Exited` 且已被删除（不再出现在列表中）

## 6. 构建 Docker 镜像

### 6.1 检查是否已有镜像

```bash
docker images roboagent:4090-cuda
```

- **预期输出**:
  - 有镜像 → 显示 `roboagent   4090-cuda   ...` 和创建时间
  - 无镜像 → 无输出（空）
- **判断**: 如果镜像存在且是最近构建的，可以跳过构建步骤直接启动

### 6.2 构建镜像（首次或需要更新时）

```bash
# 切换到 llm-r005 目录（Dockerfile 在那里）
cd /mnt/e/Claude_roboagent/llm-r005

# 构建镜像
docker build -t roboagent:4090-cuda -f 4090.Dockerfile .
```

- **参数说明**:
  - `build` — 构建 Docker 镜像
  - `-t roboagent:4090-cuda` — 给镜像打标签（tag），格式为 `名字:标签`
  - `-f 4090.Dockerfile` — 指定使用的 Dockerfile（如果不指定，默认用 `Dockerfile`）
  - `.` — 构建上下文路径（当前目录），Docker 会把该目录下所有文件发给构建引擎
- **耗时**: 约 10-30 分钟（取决于网络和编译速度）
- **预期输出**: 各构建步骤 `STEP 1/xx ... → STEP n/xx ...`，最终显示 `Successfully tagged roboagent:4090-cuda`
- **风险**:
  - 构建会大量消耗 CPU 和内存，期间电脑可能变慢
  - 需要网络下载 llama.cpp 源码（约 500MB），确保网络稳定
  - 如果构建中断，重新执行即可，Docker 会缓存已完成的步骤

**常见构建错误**:

| 错误信息 | 原因 | 解决方法 |
|---------|------|---------|
| `failed to fetch https://github.com/...` | 网络无法访问 GitHub | 检查网络，重试。或手动下载 llama.cpp 放到同级目录，修改 Dockerfile 用 COPY 替代 git clone |
| `CUDA driver version insufficient` | CUDA 版本不匹配 | 确认 Dockerfile 中的 CUDA 版本（12.4）与主机一致 |
| `No such file: 4090.Dockerfile` | 当前目录不对 | 先 `cd /mnt/e/Claude_roboagent/llm-r005` |

## 7. 启动推理服务

### 7.1 使用 Docker Compose 启动

```bash
# 启动所有 3 个服务（后台运行）
docker compose -f 4090_test/docker-compose.4090.yaml up -d
```

- **参数说明**:
  - `compose` — Docker Compose 多容器编排
  - `-f 4090_test/docker-compose.4090.yaml` — 指定 compose 配置文件
  - `up` — 创建并启动容器（等同于 `create + start`）
  - `-d` — detached，后台运行（不加 `-d` 会前台输出日志，按 Ctrl+C 会停掉容器）
- **预期输出**:
  ```
  [+] Running 3/3
   ✔ Container qwen35-4090     Started
   ✔ Container robobrain-4090  Started
   ✔ Container qwen35-08b-4090 Started
  ```
- **注意**: 第一次启动需要加载模型 GGUF 文件（约 2-5 GB），前 30 秒可能显示 `starting` 或 `healthy: starting`

### 7.2 启动单个服务（可选）

```bash
# 只启动某个模型
docker compose -f 4090_test/docker-compose.4090.yaml up -d qwen35-2b

# 可选的其他服务名: robobrain、qwen35-08b
```

### 7.3 端口映射说明

| 服务 | 内部端口 | 外部端口 | URL |
|------|---------|---------|-----|
| Qwen3.5-2B | 8080 | **8081** | http://localhost:8081 |
| RoboBrain2.5-4B | 8080 | **8082** | http://localhost:8082 |
| Qwen3.5-0.8B | 8080 | **8083** | http://localhost:8083 |

- 所有容器内部都在 8080 端口监听，通过 Docker 端口映射到不同外部端口
- `"8081:8080"` 表示 "外部访问 8081 → 转发到容器内 8080"

## 8. 检查服务运行状态

### 8.1 容器运行状态

```bash
docker ps
```

- **预期输出**: 3 个容器都在 `STATUS` 列显示 `Up`（绿色），`PORTS` 列显示端口映射
- **排查**:
  - 容器数量少于 3 → 部分启动失败，用 `docker logs 容器名` 查看日志
  - `STATUS` 显示 `Exited` 或 `Restarting` → 启动失败，排查日志

### 8.2 检查模型加载日志

```bash
# 查看某个容器的启动日志（确认模型加载完成）
docker logs qwen35-4090 --tail 30
```

- **参数说明**:
  - `logs` — 查看容器日志
  - `--tail 30` — 只显示最后 30 行（不指定则显示全部日志）
- **正常日志应包含**:
  ```
  ...
  nner_kv_size = ...
  ...
  model loaded
  ...
  HTTP server listening on http://0.0.0.0:8080
  ```
- **排查**:
  - 日志停留在模型加载阶段 → 等待 1-2 分钟（大文件加载慢）
  - 报 `GGUF` 相关错误 → 模型路径不对，检查 compose 文件中的 `-m` 参数路径
  - 报 CUDA 错误 → GPU 分配问题，检查 `nvidia-smi` 显存够不够

### 8.3 一键健康检查

```bash
bash 4090_test/test_4090.sh check
```

- **作用**: 检查 Docker、GPU、3 个服务的 HTTP 健康端点
- **预期输出**:
  ```
  ============================================
    4090 推理服务健康检查
    ...
  ============================================
    [OK] Docker 运行中
    [OK] GPU 可用
    [OK] Qwen3.5-2B (:8081) 在线
    [OK] RoboBrain2.5-4B (:8082) 在线
    [OK] Qwen3.5-0.8B (:8083) 在线
  ```
- **排查**:
  - `[FAIL] 容器状态: not_found` → 容器未启动，执行 `docker compose up -d`
  - `[FAIL] xxx 未响应` → 容器运行中但 HTTP 未就绪，等 30 秒后重试。或检查日志
- **风险**: 无

### 8.4 直接使用 curl 手动检查（备选）

```bash
# 测试 HTTP 接口是否响应
curl -sf http://localhost:8081/health && echo " 2B OK"
curl -sf http://localhost:8082/health && echo " 4B OK"
curl -sf http://localhost:8083/health && echo " 0.8B OK"
```

- **参数说明**:
  - `-s` — silent，静默模式（不显示进度信息）
  - `-f` — fail，HTTP 错误码时返回非 0 退出码
- **预期输出**: 空（无输出就是正常）或 `OK` 提示
- **注意**: `/health` 端点不返回 JSON，成功是空响应 200

## 11. 停止服务

### 11.1 停止所有服务（保留容器）

```bash
# 停止但不删除容器（下次可直接 docker start）
docker compose -f 4090_test/docker-compose.4090.yaml stop
```

- **作用**: 停止容器进程，但不删除容器元数据。下次用 `docker start` 或 `docker compose up -d` 可快速恢复
- **风险**: 不释放容器名，但释放端口和显存

### 11.2 完全下线（删除容器）

```bash
# 停止并删除容器（释放容器名、网络、磁盘）
docker compose -f 4090_test/docker-compose.4090.yaml down
```

- **作用**: 完全清除容器（但保留镜像和 volumes）
- **参数对比**:
  - `stop` → 暂停，可恢复
  - `down` → 删除，需重建

### 11.3 清理所有数据（包括日志 volumes）

```bash
docker compose -f 4090_test/docker-compose.4090.yaml down -v
```

- **参数说明**: `-v` — 同时删除 volumes（日志等数据）
- **风险**: ⚠️ 日志会被永久删除。确认不需要了再执行

## 12. 常见问题排查

### 12.1 端口冲突

**现象**: `docker compose up -d` 报 `port is already allocated`

**原因**: 有旧容器或进程占用了端口（8081/8082/8083）

**排查**:
```bash
# 查看哪个进程占用了端口
sudo lsof -i :8081
# 或者
netstat -tlnp | grep 8081
```

**解决**:
```bash
# 方法 1: 停止占用端口的容器
docker stop 旧容器名

# 方法 2: 杀掉占用端口的进程
sudo kill -9 进程PID
```

### 12.2 模型加载失败

**现象**: 容器启动后反复重启，日志显示 `error loading model`

**原因**: Compose 文件中 `-m` 路径指定的 GGUF 文件不存在

**排查**:
```bash
# 进入容器检查模型文件是否存在
docker exec -it qwen35-4090 ls -la /app/models/
```

**解决**: 修正 `docker-compose.4090.yaml` 中的 `command` 路径。

**确认模型文件结构**:
```
/mnt/e/Claude_roboagent/llm-r005/models/
├── Qwen3.5-2B-Q4_K_M.gguf      ← qwen35 用的文件
├── mmproj-F16.gguf              ← 视觉投影文件（仅 2B 需要）
├── RoboBrain2.5-4B.Q4_K_M.gguf ← robobrain 用的文件（注意是点分隔符）
└── Qwen3.5-0.8B-Q4_K_M.gguf    ← 0.8B 用的文件
```

### 12.3 Symlink（符号链接）解析失败

**现象**: 容器启动后日志显示 `GGUF` 文件不可读或文件不存在，但在 Windows 下该文件存在

**原因**: 模型 GGUF 文件可能是 Windows 上的 symlink（快捷方式），指向其他路径。Docker 容器没有挂载目标路径

**检查**:
```bash
# 在 WSL 中查看文件是否是 symlink
ls -la /mnt/e/Claude_roboagent/llm-r005/models/Qwen3.5-2B-Q4_K_M.gguf
# 如果显示如: Qwen3.5-2B-Q4_K_M.gguf -> /mnt/e/Projects/.../xxx.gguf
# 说明是 symlink
```

**解决**: 修改 `docker-compose.4090.yaml`，添加额外 volume 挂载 symlink 指向的真实路径：

```yaml
volumes:
  - /mnt/e/Claude_roboagent/llm-r005/models:/app/models:ro
  - /mnt/e/Projects/r005Test/models:/mnt/e/Projects/r005Test/models:ro  # ← 加这行
```

### 12.4 GPU 不可用

**现象**: `nvidia-smi` 报错或容器内无法识别 GPU

**排查**:
```bash
# 在 Windows 中检查 GPU 驱动
# 打开 cmd 或 PowerShell:
nvidia-smi

# 在 WSL 中检查
nvidia-smi
```

**解决**:
1. 确保 Windows 安装了最新 NVIDIA 驱动（Game Ready 或 Studio 驱动均可）
2. 确保 WSL2 已启用 GPU 加速：Windows → 设置 → 应用 → 可选功能 → WSL 更新
3. 确保 Docker Desktop 启用了 WSL 2 backend 和 GPU 支持

### 12.5 Docker 服务未运行

**现象**: `docker ps` 报 `Cannot connect to the Docker daemon`

**解决**:
```bash
# 启动 Docker 服务
sudo service docker start

# 验证
docker info
```

**如果上述无效**: 确保 Docker Desktop for Windows 已安装并在运行（系统托盘有 Docker 图标）

### 12.6 Unicode / 中文编码错误

**现象**: 运行 `test_interactive.py` 报 `surrogate U+DC00..U+DFFF must follow U+D800..U+DBFF`

**原因**: WSL 从 Windows NTFS（`/mnt/e/`）读取中文文件时，编码转换出现损坏

**排查**:
```bash
# 检查文件编码
file test_interactive.py
# 应显示: UTF-8 Unicode text

# 定位非法代理对（参考行号在报错信息中）
grep -n '行走' test_interactive.py
```

**解决方法**（按优先级）:
1. 将脚本复制到 WSL 内部路径运行（推荐）:
   ```bash
   cp /mnt/e/Claude_roboagent/r005_rebuildtest/test_interactive.py ~/
   cd ~ && python3 test_interactive.py --port 8081
   ```
2. 简化含中文的提示词模板，去掉复杂中文字符序列
3. 在 Windows 端重新保存为 UTF-8 无 BOM 格式

### 12.7 镜像磁盘空间不足

**现象**: Docker build 报 `no space left on device`

**解决**:
```bash
# 清理未使用的 Docker 数据
docker system prune -f

# 查看 Docker 磁盘使用
docker system df
```

**风险**: `prune` 会删除所有停止的容器和未使用的镜像。如果有其他项目在跑，谨慎执行。

### 12.8 完整重置流程（出大问题时用）

```bash
# 1. 停掉并删除所有容器
docker compose -f 4090_test/docker-compose.4090.yaml down

# 2. 删除镜像（下次需要重新构建）
docker rmi roboagent:4090-cuda

# 3. 清理 Docker 系统（⚠ 会删所有未用资源）
docker system prune -a

# 4. 重新构建和启动
docker build -t roboagent:4090-cuda -f ../4090.Dockerfile .
docker compose -f 4090_test/docker-compose.4090.yaml up -d
```
